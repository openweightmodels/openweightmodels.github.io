Overview

Large model, sparse activation.

Llama 4 Maverick is an autoregressive Mixture-of-Experts model with native multimodal early fusion. Meta documents 17 billion activated parameters, approximately 400 billion total parameters and 128 experts.

The active-parameter figure should not be interpreted as a 17B-class memory footprint. The deployment must still accommodate the much larger total weight set, which is why Maverick remains a datacenter-scale self-hosting workload despite sparse activation.

Architecture

Mixture-of-Experts

Sparse activation improves compute efficiency relative to activating the entire parameter set on every token.

Modality

Text + image input

Meta documents native multimodal processing through early fusion and text/code output.

Operational reality

Datacenter-class self-hosting

The 400B total parameter footprint makes hardware planning materially different from the 17B active figure.

Hardware

Do not size Maverick as a 17B model.

17B is the activated-parameter count, not the total model size. Hardware data should therefore be stored with its source and deployment context rather than collapsed into one universal “required GPU” field.

Base architecture

400B total parameters

The full weight set drives storage and memory planning even though sparse routing activates only part of the network per token.

Official FP8

Reduced footprint

Meta publishes an official FP8 Maverick checkpoint in addition to BF16.

Validated NIM path

8× H100 or H200

NVIDIA's current Maverick NIM support matrix validates homogeneous eight-GPU H100/H200 nodes.

Why this matters for the registry

“Hardware requirement” is not a single model property. OpenWeightModels should store developer claims, validated provider configurations and editorial estimates as distinct evidence types.
