Definition

What is an open-weight model?

An open-weight model is an AI model whose trained parameters are made available for download, allowing users to run the model on infrastructure they control.

The phrase describes access to model weights. It does not by itself guarantee that training data, training code, full methodology or every usage right is open. Those details depend on the model and its license.

This distinction matters. OpenAI describes gpt-oss as open-weight and publishes it under Apache 2.0 plus a usage policy, while Meta states that Llama uses a bespoke community license. Always inspect the exact model card and license before production use.

Why it matters

Open weights change where AI can run.

For many teams, the key advantage is not “free AI.” It is control over deployment, customization, latency, privacy and infrastructure.

01

Infrastructure control

Deploy on local workstations, private clouds, data centers or edge devices when the model and hardware allow it.

02

Customization

Fine-tune, adapt, quantize or package weights with compatible tooling — subject to the model's terms.

03

Data control

Self-managed inference can keep prompts and outputs inside infrastructure chosen by the operator.

04

Runtime choice

Use vLLM, SGLang, llama.cpp, Ollama or vendor-specific tooling where supported.

Licensing

Weights are open. Rights still vary.

The license is part of the model architecture decision. Check commercial use, redistribution, derivative works, attribution and restrictions.

Permissive

Apache 2.0

Common in open-model releases. It generally permits use, modification and redistribution while providing explicit patent terms.

Community

Model-specific licenses

Some major families use custom licenses. Their conditions can differ materially from standard open-source software licenses.

Operational

Usage policies

A permissive license can coexist with separate acceptable-use or safety policies. Review the complete release terms.

Rule of thumb:Never infer commercial rights from the words “open,” “open model” or “open weight.” Read the model-specific license.
Hardware

Model size is only the beginning.

Practical deployment depends on parameter count, active parameters, precision, KV cache, context length, batch size and runtime overhead.

First-order estimate
weight memory ≈ parameters × bytes per parameter
FP16 ≈ 2 B/parameterINT8 ≈ 1 B/parameter4-bit ≈ 0.5 B/parameter*

VRAM

GPU memory determines whether weights, cache and runtime buffers fit on one accelerator or must be split across devices.

RAM & offload

CPU memory and offloading can make larger models accessible, typically with latency and throughput trade-offs.

Quantization

Lower precision can reduce memory needs substantially, but quality, speed and compatibility depend on method and runtime.

* Approximation for raw weight storage only. Real deployments require additional memory.

FAQ

Open-weight models, clearly explained.

Are open-weight models the same as open-source models?

No. Open weights means trained parameters are available. Open source is broader and may imply access to code, training details or other components under qualifying licenses.

Can open-weight models be used commercially?

Sometimes, but not automatically. Commercial rights depend on the model-specific license and accompanying terms.

Can I run open-weight models locally?

Many can be run locally, especially smaller or quantized models. Feasibility depends on size, precision, runtime and available CPU, GPU, RAM and VRAM.

Why publish structured model data?

Structured records make consistent comparisons easier and allow tools, search systems and AI agents to consume the same verified metadata.

Is this a benchmark leaderboard?

No. This is designed as an operational reference. Benchmarks can be evidence, but deployment, licensing and reproducibility are first-class attributes.
